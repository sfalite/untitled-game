# Chaos City.io development rules

Read `llms.txt` before changing SDK code. Keep `sim.ts` deterministic: no `Date`, timers, `Math.random`, browser globals or network calls. The game uses Planck/Box2D through `@moddio/sim/planck`; coordinates are pixels, physics uses 32 pixels per metre, and the Planck adapter is canonicalized every 100 ticks. The current branch uses `predict: 'world'` as a controlled EXPERIMENT to test whether one predicted timeline improves weapon/projectile alignment. This mode costs more CPU and previously caused remote-player snapping. Keep the v31 `predict: 'self'` package as rollback; revert if live tests show snapping, jitter, or CPU issues.

The player sprite is 43×35 and looks up by default. Render it and its held weapon with `aimAngle + Math.PI / 2`; bullets use `aimAngle`. Keep the player fingerprint's x/y in game pixels, not Planck metres. Tree artwork remains 128×128, while the trunk collision is a centered 15×15 circle (radius 7.5 px). Keep the city map and simulation collider geometry in sync. Preserve the unmarked roads and continuous cached floor rendering.

Inventory is five slots with item IDs 0-4 for firearms and item ID 5 for the knife; players start with the Glock-17 in slot 1 and remaining slots empty. Brown crates can drop the AK-47, M249, M134, Shotgun, or knife (never the starting Glock); E picks up and G drops. Empty slots punch; the knife deals 36 damage (3x the 12-damage fist punch). Ordinary props have 20 HP, cars 200 HP, and buildings 1000 HP with a 6000-frame (5-minute at 20 Hz) respawn. Keep all damage and respawn decisions authoritative in `sim.ts`. Keep every damage, pickup, drop, and bullet collision decision authoritative in `sim.ts`.

For responsive shooting, predict local audio and one world-space muzzle flash keyed by owner/token; visible projectiles come from one shared `state.bullets` list in this world-prediction experiment, not a second provisional collection. The typed input includes `shotToken: u32`; every accepted authoritative bullet stores its client shot token and pellet index. A queued shot must never keep a world-space origin captured before a cooldown wait: when accepted, calculate the muzzle from the current authoritative player position and aim. Never move an in-flight bullet to the shooter's current muzzle. F4 collision debug must not draw a second bullet marker over the real projectile. Keep the same muzzle offsets and firing rules on client and sim. Seed the local shot-token baseline from the merged player returned by `mergeSelf`, because `state.players[game.player]` may not contain the self-predicted player. Capture short pointer clicks as one-shot input pulses, filter inventory clicks, and ensure each pulse is consumed once. Single-projectile guns follow the cursor exactly and shotgun pellets use the same deterministic fan on all clients. Do not add `inputLead: false` as a shortcut; SDK docs reserve it for games without local prediction.

Keep the current `game` slug in `moddio.json`, relative asset paths, responsive HUD and touch controls. Run `npx moddio test` and `npx moddio play --players 2 --seconds 8 --shots 3,5` after sim changes, then test 2-3 live modd.io clients. This branch is experimental; do not assume WORLD is better until weapon alignment, remote movement, and CPU are checked. Do not claim official runtime validation if only local TypeScript/static checks were run.
